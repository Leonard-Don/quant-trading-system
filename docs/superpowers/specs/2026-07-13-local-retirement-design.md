# Quant Trading 本地退役设计

## 目标

在删除 `/Users/leonardodon/quant-trading-system` 前，只保留经审核仍适用于最新 `origin/main`、能够通过相应验证的代码，并将这些代码提交和推送到 GitHub。删除未被 Git 跟踪的环境配置、缓存、模型、数据库和运行历史，不将它们上传或长期归档。

## 设计确认时的本地状态

- 本地 `main` 落后 `origin/main` 五个提交。
- `scripts/start_system.sh` 有一组未提交的虚拟环境和启动可靠性修改。
- 两个旧 stash 分别包含大规模导入整理 WIP 和一项 Policy Radar 前端修改。
- `fix/audit-docs-quick-wins` 的本地提交与远端主线存在补丁等价版本，因此不作为独立成果保留。
- 十个同名本地标签与 GitHub 标签指向不同历史；这些标签不作为产品代码迁移。
- `.env`、`data/`、缓存、构建产物和日志不在保留范围。

## 审核与整合

1. 在工作区外的临时目录中导出当前工作区和 stash 补丁，作为整合过程中的短期回退手段；不复制 `.env` 或本地数据。
2. 将 `main` 更新到最新 `origin/main`，不覆盖尚未审核的工作。
3. 单独审核启动脚本：确认虚拟环境选择、依赖检查与安装、后端/worker 解释器、tmux 环境传递和进程启动行为仍适用于最新版；删除重复或无效分支。
4. 将两个 stash 拆分审核。仅移植仍能解决当前代码问题、且不是主线已有实现的最小改动；机械格式化、破损导入整理、过时 UI 修改直接丢弃。
5. 每组保留修改形成聚焦提交，提交信息使用中文，并保持工作区无无关改动。

## 验证门槛

- Shell 修改至少通过 `bash -n`，并运行系统与 worker 启动脚本提供的非破坏性帮助或状态入口。
- Python 修改运行 Ruff 基线检查以及 `tests/unit`、`tests/integration` 中相应测试；若修改范围横跨多个模块，则运行项目规定的完整非性能测试集。
- 前端修改运行对应 Vitest；涉及构建链时补充生产构建。
- 所有保留修改必须通过相关验证；无法修复或无法证明价值的旧 WIP 不提交。
- 推送或合并后重新 fetch，确认所有保留提交已经进入 `origin/main`，本地 `main` 与 `origin/main` 一致，且不存在未提交、未推送或未审核的代码。

## 删除门槛

只有在验证和远端一致性检查完成后，才删除项目目录及空的 Superpowers worktree 遗留目录。删除包含 `.env`、本地数据库、缓存、模型和历史记录；这些内容不会上传。删除前将已验证的远端 `main` SHA 写入仓库外临时标记，删除后再次精确比对远端 SHA，成功后清除标记；同时验证项目路径不存在，并确认没有进程或启动项仍引用该路径。

## 失败处理

任何测试失败、推送失败、远端分支保护或不可解释的本地差异都会暂停删除。短期补丁只用于恢复审核中的代码；完成远端验证后明确删除临时补丁。
